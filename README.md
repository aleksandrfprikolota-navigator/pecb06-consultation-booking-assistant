# ИИ-ассистент записи на консультацию

Telegram-бот записывает клиента на консультацию по цифровым продуктам и автоматизации бизнес-процессов.

Бот:

- ведёт диалог в Telegram;
- собирает обязательные поля и не переспрашивает то, что уже известно;
- проверяет имя, контакт, тему, дату и формат;
- извлекает данные из свободного текста через LLM;
- формирует структурированную заявку;
- отправляет её в Telegram-чат администратора.

## Что собирает ассистент

- имя клиента;
- контакт: телефон или Telegram;
- тему консультации;
- удобные день и время;
- формат: онлайн, в офисе или по телефону.

Имя — это одно, два или три слова без цифр. Контакт — `@username` или телефон из 10–15 цифр. Тема не может быть ответом вроде «да» или «не знаю». Дата сохраняется только вместе со временем и не может быть в прошлом. Формат принимает значения «онлайн», «в офисе» и «по телефону»; «очно» записывается как «в офисе», «созвон» — как «по телефону».

## Как работает

1. Клиент отправляет `/start` или сразу пишет текст.
2. Бот создаёт сессию в памяти. Если в Telegram есть `@username`, он подставляется в контакт.
3. `OpenAISupportAssistant` получает текущую заявку, новое сообщение и короткую историю.
4. Модель возвращает JSON: текст клиенту, найденные поля и признак `ready_to_submit`.
5. Некорректное поле отбрасывается, бот объясняет ошибку и задаёт тот же вопрос ещё раз.
6. Когда все поля корректны, заявка уходит администратору. Клиент получает подтверждение, что время ещё будет подтверждено.
7. Команда `/reset` начинает запись заново. Голос, фото и файлы бот не разбирает и просит написать текстом.

Сессии хранятся в памяти процесса. После перезапуска контейнера незавершённый диалог пропадает.

## Переменные окружения

```env
TELEGRAM_BOT_TOKEN=your_telegram_bot_token
OPERATOR_CHAT_ID=-1001234567890
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=https://api.openai.com/v1
LOG_LEVEL=INFO
```

`TELEGRAM_BOT_TOKEN` выдаёт BotFather. `OPERATOR_CHAT_ID` — чат, куда падает готовая запись. Бот должен быть участником этого чата и иметь право писать сообщения. Для супергруппы и канала к числу из адреса веб-версии Telegram дописывают префикс `-100`: если в адресе видно `1234567890`, в `.env` записывают `-1001234567890`.

`OPENAI_API_KEY`, `OPENAI_MODEL` и `OPENAI_BASE_URL` задают модель, которая совместима с Chat Completions. Для `gpt-4.1-mini` запрос уходит с `temperature=0.2`. Если модель принимает только температуру по умолчанию, бот повторяет запрос без этого параметра.

Файл `.env` не коммитится и не копируется в образ. Шаблон лежит в `.env.example`.

## Запуск через Docker

Нужен запущенный Docker Desktop. Команды выполняются в папке, где лежит `Dockerfile`.

1. Создайте файл окружения и заполните его:

```powershell
Copy-Item .env.example .env
```

2. Соберите образ. Точка в конце обязательна: это текущая папка.

```powershell
docker build -t support-bot .
```

3. Запустите контейнер в фоне. Флаг `-d` оставляет бота работать после закрытия терминала.

```powershell
docker run --name bot --env-file .env -d support-bot
```

4. Проверьте состояние и журнал:

```powershell
docker ps --filter name=bot
docker logs bot
```

О запуске говорят строки `Starting consultation booking bot`, `Start polling` и `Run polling for bot @...`. После этого боту можно отправить `/start`.

Остановить и удалить контейнер:

```powershell
docker stop bot
docker rm bot
```

После изменения кода контейнер нужно создать заново. Старый контейнер продолжает работать из предыдущего образа:

```powershell
docker rm -f bot
docker build -t support-bot .
docker run --name bot --env-file .env -d support-bot
```
